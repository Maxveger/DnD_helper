Репозиторий: [Maxveger/DnD_helper](https://github.com/Maxveger/DnD_helper).

## Получить исходники на другом компьютере

Для разработки нужны Git, Python 3.12 и uv. Прежний готовый демопакет запускается без этих инструментов. Для текущего помощника отдельно требуется Codex; обновлённый Windows-пакет ещё предстоит проверить.

```bash
git clone https://github.com/Maxveger/DnD_helper.git
cd DnD_helper
uv sync --frozen
uv run --frozen python -m dnd_helper
```

Установку uv на Windows описывает [README](../README.md). Публичные исходники можно скачать без приглашения. Для отправки изменений нужны права участника и вход в соответствующий GitHub-аккаунт. На своей машине настройте собственный способ аутентификации GitHub; чужие ключи в репозиторий не передаются.

## Небольшое изменение

Начните с актуальной основной ветки и создайте свою:

```bash
git switch main
git pull --ff-only
git switch -c improve-hints
```

Измените нужные файлы и проверьте результат:

```bash
uv run --frozen pytest -q
uv run --frozen ruff check dnd_helper tests scripts
git diff
```

Добавьте именно изменённые файлы. Например, для изменения ядра и его проверки:

```bash
git add dnd_helper/engine.py tests/test_engine.py
git commit -m "Improve hints for unavailable actions"
git push -u origin improve-hints
```

На GitHub создайте Pull Request в `main`, опишите поведение и дождитесь зелёных проверок. После просмотра и объединения изменений обновите локальную основную ветку через `git pull --ff-only`.

Не добавляйте ключи и файлы из `data/`: они исключены через `.gitignore`. Готовые пакеты из `dist/` передаются отдельно от Git-истории. Проверяйте `git diff --cached` перед коммитом.

## Скачать проверенный выпуск

Откройте [v0.1.0-rc.1](https://github.com/Maxveger/DnD_helper/releases/tag/v0.1.0-rc.1) и скачайте `DnD-Helper-windows-x64.zip` из **Assets**. Там же находятся SHA-256 и архив исходников. Это предварительный выпуск на проверенном коммите `c982eab`. Полностью распакуйте ZIP и запустите exe, сохранив `_internal` рядом. **Текущего `/world` и обновлённого интерфейса в этом кандидате нет.**

Локальная копия может храниться в `dist/releases/v0.1.0-rc.1/`: эта папка исключена из Git. В рабочей папке разработчика туда скачаны все три вложения и сохранён `RELEASE.json` с происхождением и контрольными суммами.

## Скачать более новую сборку из Actions

1. Откройте [Actions](https://github.com/Maxveger/DnD_helper/actions/workflows/check.yml).
2. Выберите успешный запуск для нужного коммита, где `check (windows-latest)` завершён зелёным.
3. В разделе **Artifacts** скачайте **DnD-Helper-windows-and-source**. Для скачивания может потребоваться вход в GitHub.
4. Распакуйте скачанный архив. Внутри находятся Windows ZIP, его SHA-256 и отдельный архив исходников.
5. Полностью распакуйте `DnD-Helper-windows-x64.zip`, затем запустите `DnD-Helper.exe` в папке `DnD-Helper`. Папка `_internal` должна оставаться рядом.
6. Сверьте состав сборки с коммитом: подготовленное демо запускается без ключей, текущий помощник использует отдельный вход Codex. API-ключи в «Подключениях» относятся к прежнему режиму.

Artifacts хранятся 30 дней. У выпуска v0.1.0-rc.1 уже есть постоянная страница Releases; промежуточные сборки остаются в Actions.

## Что означает зелёная сборка

На Linux и Windows проходят автоматические тесты и запуск из исходников. На Windows дополнительно собирается exe, проверяется его старт/повторный запуск/восстановление, а браузер проходит импортированное приключение. Настоящие ключи Telegram/OpenAI в CI не используются.

Windows runner GitHub не заменяет пробный запуск на ноутбуке ведущего с Windows 10/11. Для текущего помощника дополнительно нужны проверка `/world` в пакете, установка/вход Codex и живая игра. Telegram с телефона проверяется отдельно для подготовленного режима.

При падении теста сводка Actions содержит сообщение с причиной. Подробный журнал находится внутри соответствующего шага; XML тестов и доступные скриншоты сохраняются отдельным диагностическим артефактом.

## Публикация следующего кандидата

`Publish verified release` переносит существующий успешный артефакт в предварительный выпуск, без пересборки. `.github/release-request.json` фиксирует тег, полный SHA коммита, номер успешного CI, ID артефакта, SHA-256 внешнего архива и файл примечаний. Проверяется также контрольная сумма Windows ZIP.

**Изменение этого файла в `main` запускает публикацию.** Перед отправкой подготовьте примечания и тег на проверенном коммите. Для повторного запуска той же заявки используйте `workflow_dispatch` в Actions. Существующие теги не перемещаются, вложения с другой контрольной суммой не перезаписываются. Выпуск открывается после проверки всех вложений.

Для публикации используется временный токен GitHub Actions с чтением артефактов и записью Releases. Ключи Telegram/OpenAI и личный API-токен разработчика не нужны.
