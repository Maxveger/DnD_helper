# Свои приключения: из чата в игру

## Путь ведущего

1. В приложении откройте **«Мои сценарии» → «Скопировать промпт для GPT»**. Вставьте в новый браузерный чат. Промпт уже включает возможности движка, точную схему и пример. Кнопка скачивания даёт тот же текст файлом.
2. Обсудите с чатом мир, жанр, персонажей, длительность, правила и сюжет. Если разговор уже состоялся, вставьте задание в тот же чат и попросите использовать договорённости.
3. Напишите **«Собери документ»**. Получите полный `adventure.json` или один блок JSON.
4. Вставьте ответ в приложение или выберите файл. Нажмите **«Проверить документ»**. Один блок Markdown и UTF-8 BOM допускаются; пересказ, PDF/Word и несколько документов подряд — нет.
5. При ошибках нажмите **«Скопировать задание на исправление»** и верните его в тот же чат. Там уже будет перечень полей и рекомендаций. Загрузите полный исправленный документ снова.
6. Посмотрите название, правила и предупреждения. Нажмите **«Добавить в библиотеку»**, затем **«Играть»** у нужной истории, выберите героев и деморежим/Telegram.

Вести игру можно без API: готовы тексты, действия и проверки. GPT API нужен для разбора свободных формулировок и голосовых. Создание документа в отдельном браузерном чате не использует ключи приложения. Готовый документ проверяется локально, без отправки в GPT.

Для знакомства нажмите **«Открыть пример»**: «Последний сигнал», космическая история с тремя локациями, двумя персонажами и d6. Это отдельное приключение, без кода водокачки. Старое «Сердце водокачки» остаётся встроенным и использует свой прежний модуль.

## Контракт

- Формат документа: `dnd-adventure@1`.
- Исполнитель правил: `declarative@1`.
- Версия конкретного приключения: `major.minor.patch`, задаётся автором.
- Один UTF-8 JSON до 500 000 байт. Неизвестные поля и версии отвергаются.
- Машиночитаемая схема генерируется из проверяющих моделей приложения; отдельная вручную поддерживаемая схема не нужна.
- Полный актуальный комплект: [AUTHOR_KIT.md](AUTHOR_KIT.md). Источник промпта: [author-prompt.md](../dnd_helper/resources/author-prompt.md). Пример: [example-adventure.json](../dnd_helper/resources/example-adventure.json).

| Раздел | Содержимое |
|---|---|
| `title`, `summary`, `lore` | Название, завязка и вводная о мире |
| `gm_notes` | Советы и скрытые сведения ведущего |
| `rules` | Название, памятка, кубик, характеристики, явно ручные правила |
| `characters` | Готовые герои, здоровье, характеристики и предметы |
| `scenes`, `start` | Локации, входные реплики, секреты, подсказки и переходы |
| `npcs` | Имена, публичные сведения, секреты и сцены присутствия |
| `items`, `clues` | Словари предметов и открываемых сведений |
| `variables` | Изменяемые факты мира: флаги, целые числа и перечисления |
| `actions` | Намерения, условия, проверка, исходы и эффекты |
| `objectives`, `endings` | Прогресс и возможные финалы |

Ключи объектов — ID латиницей до 32 символов. Пользовательские названия и описания могут быть на русском. ID `unknown` зарезервирован для решения ведущего.

## Какие правила работают

Один из кубиков d4/d6/d8/d10/d12/d20/d100; успех при `кубик + характеристика + бонус действия ≥ сложность`. Можно менять характеристики, HP, сложности и исходы. Проверка всегда имеет обе ветки, действие без проверки — только `success`.

Условия — логическое «И» в списке. Проверяются значения переменных, открытые улики, наличие предметов и здоровье. Персонаж `actor` — автор действия, `target` — выбранный герой. Цели истории и переходы не привязаны к герою, поэтому там проверяются только переменные/улики. Проверка HP использует `ref: "hp"`.

Эффекты исполняются последовательно после подтверждения ведущим:

| Операция | Значение |
|---|---|
| `set` | Задать объявленную переменную |
| `increment` | Изменить целое в пределах minimum/maximum |
| `reveal` | Открыть улику всей группе |
| `give`, `take` | Выдать/расходовать предмет actor или target |
| `hp` | Изменить здоровье actor/target в пределах 0..max_hp |
| `move` | Переместить всю группу в сцену |
| `end` | Отметить достигнутый финал; последний эффект исхода |

`once: true` делает действие однократным для всей группы после принятия успеха **или неудачи**. В остальных случаях оно повторяемо при выполнении условий. Предметы без количеств: повторная выдача тому же герою не создаёт копию. Уникальность сюжетного предмета между героями автор описывает переменной местонахождения и условиями. Расход отсутствующего предмета отменяет всю транзакцию, включая более ранние эффекты исхода.

Абстрактная схватка может быть описана действиями и переменной здоровья противника. Отдельных автоматических ходов NPC, инициативы, бросков нескольких кубиков, магии, экономики и развития персонажей этот исполнитель не содержит. Сложные системы требуют нового программного модуля. Простое название «D&D 5e» не подключает такую систему.

`rules.manual_rules` — согласованные правила, которыми управляет ведущий. Они видны перед импортом и в памятке. Приложение не применяет их из текста. Свободное описание последствий также не меняет состояние: для автоматизации нужны эффекты.

## Защита от ошибок

Проверяются JSON, повторяющиеся ключи, размеры, версии, типы, диапазоны, ссылки, характеристики, цели эффектов, наличие обеих веток проверки и структурный путь от старта к финалу. Недопустимый документ не попадает в библиотеку и не меняет игру. Импорт повторно проверяет документ, даже если отдельная проверка уже проходила.

Статический путь не доказывает выполнимость всех условий. Наличие альтернатив после неудач, корректность сюжета, баланс, отсутствие спойлеров в публичном тексте и соответствие реплик эффектам проверяются пробным прохождением. В отчёте это обозначено явно. Ошибки не «чинятся» скрытым вызовом модели.

Текст документа не исполняется как Python, JavaScript или системные команды. Ссылки на внешние схемы и код не загружаются. В браузере текст экранируется. Модель во время игры выбирает ID из каталога текущей сцены, а приложение проверяет условия и исполняет только заранее описанные операции. Секреты и будущие исходы не передаются классификатору.

На API дополнительно используются структурированные ответы и локальная проверка: [официальная документация OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs). Браузерный чат создаёт обычный текст; проверка нашего приложения остаётся обязательной.

## Версии и сохранения

Библиотека хранится локально в `game.sqlite3`, таблица `meta`, записи `adventure:<sha256>`. Хеш вычисляется по нормализованному содержимому. Повторный импорт того же документа не создаёт дубль. Изменение даже при прежнем номере авторской версии создаёт отдельную запись.

При создании партии полная копия документа записывается в сохранение. Повторный импорт/новая редакция не меняет текущую партию. Одновременно активна одна игра; перед заменой создаётся резервная копия. Экспорт игры содержит документ вместе с секретами ведущего — это файл для ведущего, не раздаточный материал игрокам. Настройки и ключи в него не включаются. Импорт приключения и импорт сохранения — разные операции; импорт сохранений пока не реализован.

## Проверки разработчика

```bash
uv run --frozen pytest -q
uv run --frozen python scripts/smoke.py
uv run --frozen playwright install chromium
uv run --frozen python scripts/browser_import_check.py
```

Последний скрипт сам запускает временный изолированный экземпляр. Для упакованной версии передайте `--executable dist/DnD-Helper/DnD-Helper.exe` на Windows или `--executable dist/DnD-Helper/DnD-Helper` на Linux. Проверяются импорт, отчёт ошибок, другой кубик/герой, провал, лечение, переходы, финал и восстановление страницы. Настоящие ключи не используются.
