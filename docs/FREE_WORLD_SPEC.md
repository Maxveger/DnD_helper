## 1. Цель и исходная точка

Ведущий и один-два игрока без опыта проводят игру на 30–40 минут. Игроки свободно формулируют действия, разговаривают с NPC, используют предметы, исследуют места и могут отказаться от исходного задания. Приложение готовит понятное решение для ведущего, считает механику и сохраняет последовательный мир.

Основной критерий свободы: разумный подход, отсутствующий в документе автора, получает разрешение по общим правилам и фактам мира. Подготовленный каталог не ограничивает перечень возможных намерений.

Сохраняем готовые компоненты: локальный запуск, FastAPI, SQLite, веб-интерфейс, адаптеры Telegram/GPT, роли, бюджет, очередь, броски, подтверждение, отмену, упаковку Windows и передачу исходников. Текущие `SimpleRules` и `declarative@1` обслуживают прежние истории. Их работоспособность подтверждена 114 тестами и браузерными прогонами; это ещё не проверка новой LLM-механики.

Источники решений: [концепция гибридного мира](HYBRID_WORLD.md), [ТЗ первой версии](MVP_SPEC.md), замечания пользователя к интерфейсу. При расхождениях для нового режима действует этот документ; прежний режим сохраняет свой контракт.

## 2. Согласованные продуктовые ограничения

| Вопрос | Решение |

| Проверка с кубиком | Ведущий видит риск и параметры до броска; после броска принимает итог |
| Основное подключение LLM | Официальный Codex CLI, собственный аккаунт ChatGPT ведущего; обычные игры и отладка |
| Расходы API | Не более $5 на тестовую сессию по контролю приложения; это потолок, а не прогноз стоимости |
| Размещение | Приложение, база, бот и Codex CLI на ноутбуке; LLM через интернет, без отдельного платного сервера |

| Подготовка мира | Браузерный чат GPT → документ → локальная проверка → библиотека → новая игра |

Лимит $5 относится к API-вызовам нового режима, включая отдельно согласованное распознавание речи. Codex расходует лимит подписки и учитывается отдельно; автоматического перехода на платный API нет. При подготовке этого ТЗ локальные ключи, настройки и лимит прежней партии не меняются. При внедрении настройка должна явно показывать и сохранять выбранный предел; расходы всех этапов, повторов и распознавания относятся к одной сессии.

## 3. Объём первой реализации

### Обязательно

- Одна подготовленная небольшая область: деревня и несколько окрестных мест, готовые герои, несколько NPC с мотивами и один исходный конфликт. Количество начальных мест ограничивает пример, но не возможное исследование.
- Свободные переговоры, обман, убеждение, обмен, помощь, исследование, перемещение, действия с предметами и простой бой по упрощённым правилам.
- Постепенное создание мест, NPC и предметов, которых не было в начальном документе, с постоянными ID и сохранением свойств.
- Последствия выбора: отношения, обещания, владение предметами, изменения мест, игровые события и течение игрового времени.
- Возможность уйти из подготовленной сцены или отказаться от задания. Приложение продолжает мир без обязательного возврата к первоначальной цепочке.
- Память, проверка предложений, корректное знание NPC и защита секретов.
- Подтверждение, исправление, отмена, перезапуск и продолжение при отказе выбранного LLM-провайдера.
- Новый документ автора, пример, промпт и рекомендации по исправлению ошибок импорта.
- Полный первый прогон через веб и проверка того же обработчика через Telegram/голос при наличии ключей.

### За пределами этого этапа

Полная автоматизация редакции D&D, развитие персонажей, сложная экономика, тактическая карта, симуляция всего мира в реальном времени, несколько параллельных кампаний, постоянное прослушивание микрофона и автоматическое озвучивание. Незнакомая механика требует решения ведущего или отдельного модуля правил; модель не объявляет её поддержанной по одному описанию.

Простые обмены и владение предметами нужны уже сейчас; полноценная экономическая симуляция для них не требуется. Разделение группы допускается с явным местоположением каждого героя; одновременно разрешается один шаг, отдельные параллельные повествования не вводятся.

## 4. Модель мира и память

Память принадлежит приложению. История разговора с моделью и резюме не являются единственными источниками истины.

| Данные | Обязательное содержание |
| --- | --- |
| Основа мира | Жанр, ограничения, законы мира, исходная история и установленные тайны |
| Сущности | Устойчивый ID, тип, имя, свойства, местоположение/владелец, связь с источником |
| NPC | Цели, страхи, ресурсы, отношения, убеждения и известные ему сведения |
| Факты | Утверждение, связанные сущности, источник, статус, видимость и событие появления |
| Обязательства | Кто кому что обещал, условия, срок в игровом времени, состояние выполнения |
| События | Автор/причина, время, принятое последствие, ссылки на факты и сущности, версия мира |
| Открытые области | Что ещё не определено и какие дополнения допустимы |
| Игровая сессия | Версии документа, правил, состояния и инструкций; очередь, текущий шаг и расходы |

Статусы знания различаются: установленный факт, утверждение участника, слух, предположение и неизвестное. Неизвестное не равнозначно отсутствующему. Неполный результат поиска в памяти не подтверждает отсутствие предмета или NPC.

Игрок может соврать, NPC может ошибаться; такие реплики не изменяют объективные факты. Прошлое не переписывается для удобства нового сюжета. Изменение текущего состояния требует события. Явная правка основы ведущим записывается отдельно и отменяет устаревшие предложения.

Созданный NPC или место при повторном посещении сохраняет свойства. Значимые детали описания регистрируются до показа: упомянутый доступный рычаг или верёвка становятся частью мира. Чисто атмосферный текст не создаёт тайно предметы, выходы, способности или награды.

## 5. Контекст одного запроса

Контекст собирается из актуального снимка мира и включает:

1. Постоянные инструкции и контракт ответа.
2. Применимые общие правила и ограничения мира.
3. Автора, его героя, текущую сцену и используемые объекты.
4. Мотивы, знания и отношения участвующих NPC.
5. Связанные факты, обязательства и прошлые события с ID источников.
6. Последние реплики и исходное действие игрока.

При нехватке сведений выполняется ограниченный поиск в памяти или задаётся один конкретный вопрос. Модель явно отделяет найденные сведения от предлагаемых новых деталей. Для первого объёма достаточно локальных структурированных выборок и поиска; внешняя векторная база не является обязательной зависимостью.

Критические факты и обязательства не удаляются при сокращении контекста. Резюме пересобирается по принятым событиям, его версия фиксируется. Непринятые и отменённые события не попадают в текущую память как истинные.

Планировщик может получать секреты, необходимые для решения. Формирование публичной реплики и ответы конкретного NPC получают отдельное представление с разрешёнными знаниями. Секретные данные нельзя просто вложить в запрос публичного рассказчика с просьбой «не разглашать».

## 6. Полный игровой шаг

Состояния: `queued → planning → validating → clarification / review / awaiting_roll / ready → committed`. Отмена и ошибка — явные состояния без применения частичных последствий. Названия внутренние; в интерфейсе используются понятные русские подписи.

1. Приложение принимает сообщение, сохраняет ID, источник и привязанного автора. Игрок не выбирает себе чужую роль текстом сообщения.
2. Только первое действие очереди разрешается на актуальном состоянии. Для голосового сохраняется исправляемый результат распознавания.
3. LLM определяет намерение, подход, объекты, необходимые условия и возможные последствия. Сообщение с несколькими значимыми действиями разбивается на последовательность, а не выполняется целиком одной непроверенной командой.
4. Код проверяет контракт, ссылки, ограничения и актуальность. Значимые новые факты и неоднозначные решения проходят смысловую проверку.
5. Ведущий получает готовую карточку: краткая трактовка, реакция мира, механические изменения и один следующий шаг. Существенная неопределённость оформляется одним конкретным вопросом с рекомендуемым вариантом.
6. Если нужен бросок, до него фиксируются правило, сложность, бонусы, расход ресурсов и обе ветки исхода. Физический и программный броски используют один расчёт. Повторная формулировка не меняет выпавшее число и ветку.
7. Для исхода без броска и для рассчитанного результата ведущий нажимает «Принять исход». Добавление новых фактов принимается вместе с исходом; отдельного подтверждения каждого имени не требуется.
8. В одной транзакции сохраняются изменения мира, факты, событие, контрольная точка и задания доставки. Проверяется версия мира. Далее обрабатывается следующая заявка.

Ведущий видит черновик реплики до принятия. Игрокам итог доступен только после него. Если отдельный рассказчик вызывается после записи результата, его сбой не отменяет и не повторяет механику: показывается подготовленное краткое описание принятого исхода. Повторный запрос текста не перебрасывает кубик.

На паузе и после завершения партии результат не применяется автоматически. Перезапуск восстанавливает ожидающее подтверждение или бросок. Поздний ответ, отмена действия или смена версии мира не позволяют старому результату изменить состояние.

## 7. Контракты LLM и общие операции

Текущий `Plan(intent, target)` закрытого каталога остаётся для старых историй. Новому режиму требуется отдельный тип предложения со следующими полями:

- идентификаторы запроса, действия и версии мира, назначенные сервером;
- распознанное намерение, подход и ссылки на участников/объекты;
- факты-основания с ID источников, недостающие сведения и предлагаемые дополнения;
- предложенный тип проверки, категория трудности, риски и ветки исхода;
- типизированные операции каждой ветки и их предусловия;
- текст ведущему и разрешённое игрокам описание;
- признак необходимости решения ведущего с конкретной причиной.

Сервер не доверяет присланной роли, версии состояния или самооценке уверенности модели. Категорию сложности модель предлагает в рамках выбранного набора правил; модуль правил определяет числовую сложность, бонусы, урон и допустимые пределы. Спорная интерпретация показывается ведущему до броска. Успех не назначается по просьбе игрока.

Рабочий набор операций: перемещение, создание сущности/связи, передача или расход предмета, изменение допустимого состояния/отношения, применение механического эффекта, фиксация обещания, раскрытие знания, создание/продвижение события и продвижение игрового времени. У каждой операции ограничены поля и проверяются предусловия.

Свободный текст не исполняется как код, SQL или произвольная запись в JSON состояния. Новые сущности получают серверные ID; временные ссылки предложения разрешаются при проверке. Один предмет не появляется у двух владельцев. Переход группы явно перечисляет перемещаемых участников.

## 8. Защита от ошибок и противоречий

Проверка выполняется на трёх уровнях:

1. **Код:** схема, типы, ссылки, ресурсы, HP, способности, принадлежность предметов, видимость данных, версия состояния, идемпотентность и разрешённые операции.
2. **Смысловая проверка:** значимые дополнения мира, изменение отношений/обязательств, неожиданные взаимодействия и последствия для установленной истории. Проверяющий получает исходные факты, а не только резюме автора предложения; замечание содержит ссылку на основание.
3. **Ведущий:** конфликт, не разрешённый проверками, крупное необратимое последствие или явная правка основы. Карточка содержит рекомендацию; изучать трассировку запросов для продолжения не требуется.

Проверяющий — отдельный этап запроса, а не обязательно другая модель или постоянно работающий агент. Код выбирает необходимость проверки по операциям и затронутым фактам; модель не может сама объявить опасное изменение безопасным. Согласие двух LLM не доказывает истинность.

Предлагаемый предел для первой реализации: одна автоматическая попытка исправления предложения с повторной проверкой и не более пяти генеративных вызовов на обработку одного действия суммарно. Дополнительное получение контекста использует тот же предел. Счётчики и расходы сохраняются при перезапуске; автоматические повторы не образуют новый неограниченный бюджет. При исчерпании предела — решение ведущего, сохранённое действие и прежнее состояние мира. Ручной повтор явно учитывается в общей стоимости сессии.

Непрошедший проверку или незавершённый ответ не показывается игрокам. Отказ модели, неверная схема, тайм-аут, отсутствие доступа к выбранной модели и исчерпание бюджета API или лимита Codex дают понятное сообщение и ручной путь. Ни один из них не считается игровым провалом персонажа.

## 9. Динамика мира и простые правила

NPC и группы имеют цели, ресурсы и причины действовать. Изменения вне сцены привязаны к игровому времени и событиям; разговоры, повторные нажатия и задержка модели сами по себе не двигают опасность вперёд. Фоновые события используют те же проверки и показываются ведущему для принятия, отдельного автономного автора базы нет.

Для первого режима используется небольшой модуль упрощённых правил: d20, заданные характеристики и бонусы, несколько категорий трудности, помощь, предметы, HP и короткий бой. Новая формулировка действия использует общую механику; готовая ветка на каждую фразу не требуется.

Рабочая спецификация правил для первого прототипа (проектное предложение):

| Механика | Значение |
| --- | --- |
| Проверка | d20 + характеристика + допустимый бонус ≥ сложности |
| Трудность | Обычная 10, сложная 13, очень сложная 16; очевидное безопасное действие без броска |
| Начальные герои | Готовые профили Миры и Торвина с текущими характеристиками и 8 HP |
| Помощь | +2 к одной следующей подходящей проверке; не складывается сама с собой |
| Простой бой | Поочерёдные действия участников, затем противника; выбывшие не получают ход |
| Удар / перевязь | Базовый урон 2; перевязь восстанавливает до 3 HP и расходуется |
| Противник первого примера | Страж: 4 HP для одного героя, 6 для двух; собственный бросок d20 + 1 против 10 |
| Поражение в первом примере | Нелетальный исход с восстановлением до 1 HP и возможностью продолжения |

Таблица фиксируется в модуле правил и памятке нового документа, а не меняется LLM на лету. Другие противники и способности требуют поддержанных профилей; свободная генерация биографии NPC не разрешает назначить ему произвольные боевые числа. Дальнейшие модули могут использовать другие таблицы без изменения обработки сообщения и сохранения.

Если риск отсутствует и действие осуществимо, бросок не навязывается. При неудаче сохраняется понятный путь продолжения: изменение положения, затрата времени или ресурса, реакция NPC либо возможность выбрать иной подход. Нельзя гарантировать отсутствие тупика в любом созданном мире одной проверкой JSON; это предмет игровых испытаний.

## 10. Интерфейс и каналы

- Главный ввод — свободная реплика. Автор и действующий герой видны явно; Telegram определяет автора по привязке.
- Подсказанные варианты служат примерами. Среди них присутствуют доступные переходы с названиями мест; недоступные и выполненные одноразовые варианты скрыты. Свободный ввод остаётся доступным для других подходов.
- Кнопки-предложения LLM проходят тот же путь проверки, что текст. Они не позволяют обойти правила или исполнить старый план после изменения мира.
- Видны этап обработки, текущий автор и следующий ожидаемый шаг. Интерфейс не блокируется сетевым запросом; возможна отмена заявки без применения её позднего ответа.
- Без броска — одно принятие готового исхода. При броске — запрос броска и принятие результата. Настройка текущего этапа: обязательное подтверждение ведущим.
- Ведущему доступны «Исправить», «Другой текст», «Решить самому», «Пропустить», «Пауза», «Отменить последний шаг». Значимые ручные правки тоже фиксируются в памяти.
- Секреты, причины проверок и техническая диагностика отделены от реплик для игроков. Карточки показывают актуальные HP, предметы и известные персонажу сведения.
- Голосовые Telegram проходят распознавание и тот же обработчик. Постоянное прослушивание не вводится. Сетевая ошибка допускает текстовое продолжение.

## 11. Сохранение, отмена и совместимость

Снимок состояния и события сохраняются локально в SQLite. Контрольная точка предшествует принятию исхода. Для первого этапа полное восстановление исключительно проигрыванием событий не обязательно; согласованность снимка, фактов и журнала обязательна.

Отмена восстанавливает предметы, HP, позиции, отношения, знания, обязательства, созданные сущности и игровое время. Резюме и подготовленные предложения, зависящие от отменённого шага, становятся недействительными. Расходы API и привязки участников не откатываются. Уже прочитанное игроками сообщение нельзя «забыть» отменой; интерфейс сообщает об исправлении результата.

Старые документы, игры и правила продолжают работать. Новая партия закрепляет версии своего документа и исполнителя. Существующее сохранение не переводится на свободную механику автоматически. Перед миграцией структуры базы создаётся резервная копия; неподдерживаемая версия выдаёт понятное сообщение вместо сброса игры.

## 12. Авторский документ

Рабочие идентификаторы нового контракта: `dnd-world@1` для документа и `hybrid-simple@1` для исполнителя. При реализации они фиксируются вместе со схемой; существующий `dnd-adventure@1` сохраняется.

Документ содержит: жанр и завязку, правила, основу мира и тайны, стартовые места и связи, героев, NPC и их знания/мотивы, предметы и свойства, конфликты, события, открытые области, границы импровизации и возможные завершения. Перечень всех решений и единственный обязательный маршрут не требуются.

Комплект автора включает промпт для браузерного GPT, автоматически сформированную из моделей схему, полный небольшой пример и инструкцию. Локальный валидатор проверяет версии, ссылки, типы, обязательные сведения, исполнителя правил и границы объёма. Ошибка указывает поле, причину и задание для исправления в исходном чате. Импорт не выполняет платных вызовов и не запускает код из документа.

## 13. Провайдеры LLM, лимиты и диагностика

Основной провайдер — официальный Codex CLI под собственным аккаунтом ChatGPT ведущего. OpenAI Responses API остаётся альтернативой с тем же игровым контрактом. Выбор провайдера явный; автоматического платного переключения нет. Планирование, смысловая проверка и формулировка результата имеют отдельные инструкции и версии. Авторизация Codex выполняется штатным входом вне приложения; токены не копируются. API-ключ вводится в локальных настройках, не попадает в Git, игровой документ, экспорт и диагностику.

Codex получает подготовленный контекст отдельного шага, а не текущий чат разработки или доступ к игровой базе. Память остаётся в приложении. Запуск, изоляция, отмена, учёт использования, установка и проверка описаны в [CODEX_PROVIDER.md](CODEX_PROVIDER.md). Распознавание речи через отдельный API согласовано пользователем и учитывается в $5.

В подписочном режиме учитываем число запросов, доступные данные usage и задержку. Остаток лимита не угадываем; при отказе сохраняем шаг и предлагаем ручное продолжение. Ожидание одной-двух игр в неделю нужно проверить измерением. Наличие подписки не означает безлимитность; приложение не управляет биллингом купленных кредитов Codex.

Конкретная модель выбирается перед первым живым прогоном по доступности аккаунта, поддержке нужного формата, качеству и задержке. Текущий дешёвый классификатор не считается автоматически подходящим для свободного мира. Возможность разных моделей на этапах допускается, но не обязательна для первого прототипа.

Для API до каждого платного вызова резервируется верхняя оценка расходов. Сумма подтверждённых расходов и резервов не должна разрешать новые запросы сверх $5. При неизвестной цене или недостатке остатка запрос не выполняется. Если исход сетевого запроса неизвестен, резерв не обнуляется. Показания приложения могут отличаться от счёта провайдера; лимит управляет допуском запросов, а не даёт гарантию точного внешнего списания.

Отдельно учитываются подготовка, проверка, исправление, формулировка и распознавание. Локальная диагностика содержит ID шага, версии модели/инструкций/правил, выбранные источники фактов, результаты проверок, токены, задержку и статус применения. Записи с игровыми секретами не отправляются игрокам и не публикуются в CI. Секретные ключи исключаются.

Рабочие цели скорости для первого замера: 90% обычных текстовых действий — готовая карточка в пределах 15 секунд, действий с дополнительной проверкой — в пределах 30 секунд; время человека на решение не входит. Это предлагаемые цели, не подтверждённые характеристики. После измерения уточняются модель и число запросов, но проверки нельзя молча отключать ради скорости.

Живые прогоны любого провайдера запускаются отдельно от обычного CI. Для API задаётся явный бюджет, для Codex — ограниченный набор запросов и действий; личный аккаунт в CI не используется. Лимит одной игровой сессии не означает разрешения на неограниченное количество автоматических платных сессий.

## 14. Приёмка

### Механика и восстановление

- Проверены общие операции, ограничения, обе ветки броска, повтор команды, конкурентное действие и устаревший ответ.
- Предложение не меняет мир до принятия. При частичной ошибке ни один эффект не применяется.
- Перезапуск проверен при подготовке, ожидании броска и ожидании принятия. Отмена возвращает все относящиеся к миру записи; расходы сохраняются.
- Проверены отказ провайдера, неверный ответ, отсутствие CLI/входа или API-ключа, исчерпание лимита, остановка процесса и ручное продолжение. Ошибки Codex не запускают API.
- Проверены одинаковые контракты провайдеров, сохранение памяти при переключении и фактическая изоляция игрового запроса от посторонних файлов и инструментов.
- Старые встроенные и импортированные истории проходят прежние тесты и браузерные маршруты.

### Качество свободной игры с настоящей моделью

Минимальный план испытаний: одна живая игра на 30–40 минут и три сохраняемых прогона не менее чем по 40 разрешённых действий. Первый выбранный провайдер — Codex CLI. Его проверка не требует API-ключа; результаты не заменяются подставными ответами. Готовность альтернативного API проверяется отдельно в заранее ограниченном бюджете.

| Ситуация | Ожидаемый результат |
| --- | --- |
| Убедить NPC доводом, которого нет в документе | Предложение опирается на его мотивы; используются общие правила |
| Применить предмет необычным способом | Проверяются наличие и свойства; возможны новые согласованные последствия |
| Покинуть подготовленную область | Создаётся совместимое место, сохраняющееся при возвращении |
| Отказаться от задания | Игра продолжается; NPC реагируют причинно, обязательный маршрут не навязывается |
| Вспомнить обещание с раннего хода | Правильные участники, условия и статус после длинного диалога/перезапуска |
| Заявить о несуществующем предмете или способности | Утверждение не становится фактом и не обходит правила |
| Вернуться к созданному NPC | Сохраняются личность, знания, отношение и ранее принятые изменения |
| Спросить NPC о чужом секрете | Ответ соответствует его знаниям; публичный канал не получает скрытые записи |
| Потратить предмет дважды | Второе применение не проходит проверку |
| Получить противоречивый или запоздавший ответ | Нет повреждения мира; есть понятный следующий шаг ведущему |

В фиксированном наборе обязательны отсутствие несанкционированных механических изменений, повторных эффектов и раскрытия защищённых секретов; обнаруженный случай блокирует приёмку до исправления и повторной проверки. Это критерий испытаний, не обещание нулевой вероятности ошибок в любой игре.

Для смыслового качества сохраняется разметка человеком: потерянные факты, противоречия, разумные непредусмотренные действия, ручные исправления и причина каждого отказа. Отдельно считаются расход и задержки. Числовые пороги качества сверх критических нарушений устанавливаются после базового замера, без подмены живой оценки одним LLM-судьёй.

### Поставка

Новый режим проходит браузерный прогон, затем сборку и smoke-проверку Windows. Telegram/голос проверяются с настоящими настройками отдельно. До такого прогона статус каналов явно отмечен. Передаются исходники, инструкции, пример мира и отчёт с реальными результатами.

## 15. Порядок реализации

1. **Контракты и память:** сущности, факты, знания, события, версии, общие операции, модуль простых правил; тесты инвариантов.
2. **Вертикальный прототип:** один свободный ход через веб и Codex CLI, с общим контрактом для альтернативного API и его лимитом $5, карточкой предложения, проверкой и принятием. Для начала — небольшая область водокачки с мотивами NPC, без обязательной цепочки её старых кнопок.
3. **Устойчивость:** смысловая проверка, поиск в памяти, отмена и перезапуск, отказы провайдеров, лимиты, задержки и расходы; неожиданные действия и длинные прогоны.
4. **Авторский комплект:** окончательная схема нового документа, импорт, пример, промпт и исправление ошибок; совместимость старого режима.
5. **Каналы и поставка:** тот же ход через Telegram и голосовые, браузерная приёмка, Windows-пакет, проверка установки/входа Codex и инструкции.

Каждый этап сохраняет работоспособность предыдущего. К реализации контрактов можно приступить без ключа. Выбор доступной модели Codex и проверка входа нужны перед первым живым прогоном. Для альтернативного API отдельно проверяются модель, цена и ключ. Наличие доступа не подтверждает качество игры.

## 16. Ещё предстоит выбрать или измерить

- Качество выбранной Luna на длинной партии, число последовательных запросов и задержку; при необходимости — отдельную модель проверяющего. Для альтернативного API — модель и актуальный тариф.
- Баланс предложенных простых правил и профили дополнительных противников по результатам игры.
- Задержку, расход и долю ручных исправлений на живом прототипе.
- Настройки Telegram для сквозного прогона; они не блокируют первую проверку через веб.

Эти пункты не отменяют выбранный **Codex CLI как основной провайдер**, **$5 на API-вызовы сессии** и **одно принятие обычного исхода ведущим**. Реализован первый текстовый срез; дальнейший объём и ограничения указаны в [отчёте прототипа](FREE_WORLD_CHECK.md).
