# Архитектура

Приложение состоит из одного режима.

```text
browser /studio
  → web.py (localhost, CSRF, API)
  → GameStudio
      → CodexProvider: строгий игровой App Server / тред
      → CodexProvider: независимый App Server / тред редактора
      → Store: studio.sqlite3
```

`studio.py` содержит схемы карточки, капсулы и редактора, команды ведущего и фоновые workers. `codex_provider.py` обслуживает JSONL App Server, вход, схемы, тайм-аут, отмену и usage. `storage.py` даёт атомарные ревизии, квитанции команд и контрольные точки. `web.py` публикует только Studio, Codex status/login и shutdown. Статика находится в `static/studio.*`, встроенное досье — в `resources/studio-eye.json`.

Игровой и режиссёрский треды разделены. Первый игровой ответ не ждёт метамодель. После появления карточки редкий локальный сигнал может запустить её фоновую оценку; невыбранный анализ не входит в игровой промпт. Только явное решение ведущего создаёт второй игровой запрос, который заменяет текущую непринятую карточку. Текст модели не пишет базу напрямую: человек принимает итоговую капсулу транзакцией.

Единственная база продукта — `studio.sqlite3`. Корень `/` и `/studio` открывают один интерфейс.
