# Разработка и передача ведущему

## Исходные условия

Разработка ведётся на Linux. Приложение должно работать локально у ведущего на Windows 10 или 11. Ключ GPT API и токен Telegram-бота передаются пользователем отдельно от исходников и сборки. Предполагаемый канал передачи — GitHub.

Ниже — требования к поставке. Скрипты сборки и проверок, архивирования исходников и workflow Linux/Windows реализованы. Windows-пакет собран и проверен в [GitHub Actions](https://github.com/Maxveger/DnD_helper/actions/runs/34968229530); доступен как артефакт. GitHub Release ещё не опубликован, запуск на целевом ноутбуке предстоит. Актуальные команды — в [README](../README.md), пользовательская инструкция — в [PLAYER_SETUP.md](PLAYER_SETUP.md).

## Сценарий ведущего

1. Открыть ссылку на конкретный выпуск и скачать `DnD-Helper-windows-x64.zip`.
2. Распаковать архив в доступную для пользователя папку.
3. Запустить `DnD-Helper.exe`. После готовности сервера приложение открывает веб-страницу в браузере по умолчанию.
4. При первом запуске вставить отдельно полученные ключи в экран настройки. Для токена бота и API показываются отдельные результаты проверки подключения.
5. Создать сессию и пригласить игроков через Telegram.

В последующие разы нужны только запуск и выбор сохранённой либо новой игры. Командная строка, установка языка программирования, клонирование репозитория и настройка роутера не требуются.

Целевой пакет — Windows x64. Точное имя исполняемого файла можно уточнить при реализации, сохранив один очевидный способ запуска.

## Что входит в пакет

- Исполняемое приложение и необходимые ему библиотеки/runtime.
- Готовые статические файлы веб-интерфейса.
- Версионируемые данные правил и приключения.
- Короткая инструкция на русском: запуск, настройка, завершение, обновление и расположение сохранений.

Если обработка аудио требует внешнего конвертера, он включается в сборку с учётом условий распространения либо выбирается путь обработки без отдельной установки. Ведущий не устанавливает аудиоинструменты вручную.

Сборка не содержит настоящих ключей, сохранений разработчика, журналов и записей игроков.

## Данные и обновления

- Данные находятся вне папки программы: на Windows — в пользовательском каталоге приложения под `%LOCALAPPDATA%`, на Linux — в пользовательских каталогах конфигурации и данных с поддержкой XDG.
- Ключи отделены от экспортируемых игровых данных. Полные значения не показываются после сохранения и не записываются в логи или browser storage.
- Программа не требует прав администратора и не пишет в системные каталоги.
- При обновлении ведущий завершает приложение, распаковывает новую версию и запускает её. Старые ключи и сохранения подхватываются автоматически.
- Изменение схемы базы имеет номер миграции и резервную копию перед выполнением. Старой версии запрещено открывать неподдерживаемую новую схему на запись.
- Экспорт сохранения содержит версию правил и приключения и не содержит ключей. Автоматический импорт с проверкой совместимости остаётся последующим этапом; в текущем интерфейсе есть только экспорт.

## Запуск и завершение

- Один запуск поднимает необходимые компоненты. Браузер открывается только после проверки готовности локального сервера.
- Повторный запуск открывает уже работающий экземпляр, без второго бота и конфликтующих записей в базу.
- Закрытие вкладки не завершает игру и сервер. Кнопка «Завершить приложение» явно останавливает обработку и сохраняет состояние; это объясняется в короткой инструкции.
- При занятом порте выбирается доступный loopback-порт; фактический адрес передаётся браузеру.
- При отсутствии ключей открывается настройка. При недоступной сети приложение показывает состояние подключения и позволяет просмотреть сохранение.
- Параллельный запуск одного бота на компьютере разработчика и ведущего не допускается. Для разработки используется тестовый бот или реальный polling выключен перед передачей.

## Сборка и GitHub

Исходники и инструкции разработчика размещаются в репозитории. Пользовательский пакет скачивается из Releases, отдельно от кнопки скачивания исходников.

Предусмотрены два отдельных сценария: играть из готового пакета и разрабатывать из исходников. Во втором случае участник устанавливает инструменты выбранного стека и Git по инструкции для Windows. Все исходники, данные приключения, тесты и конфигурация сборки должны быть доступны; собственная сборка не зависит от компьютера первоначального разработчика. Подробности участия — в [CONTRIBUTING.md](../CONTRIBUTING.md).

Предлагаемая схема:

1. Обычные изменения проходят тесты на Linux и Windows с тестовыми провайдерами.
2. Сборка Windows выполняется на Windows runner GitHub Actions. Если backend будет на Python, кандидат для упаковки — PyInstaller в режиме папки с зависимостями, затем ZIP.
3. На собранном пакете проверяются старт, доступность веб-страницы, создание базы и корректная остановка без настоящих API-ключей.
4. Проверенный архив с номером версии прикрепляется к выпуску вместе с контрольной суммой и короткой инструкцией.

PyInstaller создаёт пакет для ОС сборки и не является кросс-компилятором: [официальная документация](https://www.pyinstaller.org/en/stable/). Поэтому разработка на Linux не заменяет Windows-сборку. GitHub Actions позволяет собирать и передавать артефакты между заданиями: [документация GitHub](https://docs.github.com/en/actions/tutorials/store-and-share-data).

Исходники опубликованы в [Maxveger/DnD_helper](https://github.com/Maxveger/DnD_helper). Пакет скачивается из Artifacts успешного запуска Actions; для постоянной ссылки его можно прикрепить к выпуску. [Инструкция по Git и скачиванию](GIT_WORKFLOW.md).

## Проверка поставки

- Чистое пользовательское окружение Windows без Python/Node.js/Git/Docker.
- Windows 10 и 11 x64: реальный или виртуальный запуск. Проверка на Windows runner сама по себе не подтверждает обе пользовательские ОС.
- Папка пользователя и папка программы с пробелами и кириллицей.
- Первый запуск, настройка, повторный запуск и корректное завершение.
- Перезапуск при ожидании броска, восстановление игры и обновление сборки.
- Отсутствие секретов в архиве, логах и экспорте.
- Реальное голосовое Telegram, распознавание и ответ GPT на целевой сборке.
- Запуск из чистого checkout на Linux и Windows по инструкции, тестовый игровой шаг без внешних ключей, выполнение тестов и воспроизводимая сборка из зафиксированных зависимостей.

Факт успешной сборки и факт прохождения этих проверок фиксируются отдельно; совместимость не объявляется проверенной только по Linux-тестам.
