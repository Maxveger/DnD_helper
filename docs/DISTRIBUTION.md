# Передача приложения ведущему

[← Путеводитель](README.md) · [Первый запуск и первая сцена](PLAYER_SETUP.md) · [Исходники, совместная работа и Windows-сборка](GIT_WORKFLOW.md)

Текущая разработка — Linux; целевая машина ведущего — Windows 10/11 x64. Передаём исходники и готовый пакет, чтобы ведущий мог играть и участвовать в учебном проекте.

## Статус поставки

Известный опубликованный кандидат [v0.1.0-rc.1](https://github.com/Maxveger/DnD_helper/releases/tag/v0.1.0-rc.1) относится к подготовленным приключениям. Его сборка и автоматические проверки прошли на Windows runner ([зафиксированный запуск](https://github.com/Maxveger/DnD_helper/actions/runs/34968229530)).

**Текущий помощник `/world`, Codex и обновлённый интерфейс в этом выпуске отсутствуют.** Для них нужна новая сборка и проверка на Windows. Запуск на реальном ноутбуке ведущего ещё предстоит. [Сводка проверок](VERIFICATION.md).

## Что устанавливает ведущий

| Компонент | Готовый пакет | Разработка из исходников |
| --- | --- | --- |
| Приложение | Распакованный ZIP: exe и `_internal` рядом; Python не нужен | Git, Python 3.12, uv и зависимости из lock-файла |
| Модель для `/world` | Отдельный Codex CLI и собственный вход ChatGPT | То же |
| Веб-интерфейс | Обычный браузер, отдельной сборки frontend нет | То же |
| Telegram/речь | Сейчас не нужны для `/world` | Отдельный будущий этап |

Если выбран npm-способ установки Codex, ему нужен Node.js. Обещание «ничего дополнительно не устанавливать» относится к прежнему демопакету приложения, а не ко всему текущему помощнику с моделью. [Как устроен адаптер](CODEX_PROVIDER.md).

## Сборка

На целевой ОС из чистого checkout:

```bash
uv sync --frozen
uv run --frozen pytest -q
uv run --frozen python scripts/build.py
uv run --frozen python scripts/source_archive.py
```

Используется PyInstaller с папкой зависимостей и ZIP в `dist/`. Сборка Linux не является Windows-сборкой. Workflow [check.yml](../.github/workflows/check.yml) выполняет тесты на Linux/Windows, собирает Windows-пакет, проверяет запуск и браузерные сценарии подготовленного режима, сохраняет архивы.

Архив исходников создаётся по явному списку: код, тесты, документация, ресурсы и конфигурация. Ключи, локальный CLI, игровые базы и личные логи не входят. Материалы лицензирования зависимостей собираются отдельно: [сторонние компоненты](THIRD_PARTY.md).

## Данные и обновление

По умолчанию данные хранятся вне программы: `%LOCALAPPDATA%\DnDHelper` на Windows и XDG-каталог `dnd-helper` на Linux. `--data-dir` переопределяет путь. Помощник использует `free-world.sqlite3`, подготовленный режим — `game.sqlite3`; ключи API/бота — `settings.local.json`. Авторизацией Codex управляет сам CLI.

Перед обновлением завершить приложение и сохранить нужный журнал/копию каталога данных. Распаковать новый пакет и запускать его с тем же каталогом данных. Совместимость обновления проверять отдельно; наличие SQLite само по себе не доказывает безопасную миграцию или откат на старую версию.

Журнал `dnd-world-log@1` можно экспортировать и загрузить с проверкой. Он содержит секреты и принятые события, без ключей и неподтверждённой карточки. Экспорт прежнего режима — другой формат без автоматического импорта. [Мир и журнал](WORLD_FORMAT.md).

Повторный запуск с тем же каталогом открывает уже работающий экземпляр. Закрытие браузера не останавливает процесс; кнопка завершения находится на основном экране `/`. На `/world` отдельной кнопки завершения пока нет.

## Приёмка следующей поставки

1. Зафиксировать нужный коммит и получить зелёные Linux/Windows-проверки.
2. Проверить **новый** `/world` в Windows-пакете, включая ресурсы мира, импорт/экспорт, правку, кубик и восстановление. Сейчас этот браузерный сценарий запускается локально отдельно от workflow.
3. На Windows проверить установку/обнаружение Codex, вход ведущего, короткую живую карточку, ошибку и отмену. Подписку в обычный CI не добавлять.
4. На ноутбуке проверить двойной щелчок, фактический адрес браузера, повторный запуск, кириллицу/пробелы в пути, перезапуск при незавершённой карточке и обновление с сохранением.
5. Провести пробную партию 30–40 минут. Результат сборки, проверку ОС и качество игры фиксировать отдельно.
6. Подготовить примечания выпуска, контрольные суммы и архив исходников; публиковать конкретный проверенный артефакт по [Git-процессу](GIT_WORKFLOW.md).

API-ключи и токен бота потребуются только для соответствующих адаптеров и передаются отдельно. Новый режим не должен молча включать платный API при ошибке Codex.
