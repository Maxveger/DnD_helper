## Проверка контракта законченной сессии — 2026-09-19

Временные игры, проектная Codex CLI 0.154.0, Luna, без пользовательского сохранения. Сначала повторена причинная последовательность из трёх заявок, затем отдельно проверена групповая карточка.

Первый последовательный запуск обнаружил три типичных расхождения между разумным ответом и строгой транзакцией: модель открыла факт без отдельной служебной отметки осмотра, повторно передала уже известные сведения и поставила взятие инструмента после перехода. Вместо требования переформулировать действия добавлена локальная нормализация: открытие фиксирует осмотр, заведомо пустая повторная передача удаляется, взятие доступного инструмента переносится перед выходом. Повтор прошёл целиком:

| Заявка | Секунды | Вход / выход | Результат |
| --- | ---: | ---: | --- |
| Мира идёт к водозабору и исследует затвор | 16,28 | 7 782 / 403 | маршрут, осмотр и открытие причины |
| Мира возвращается и сообщает Торвину причину | 10,77 | 7 525 / 394 | маршрут и постоянная передача знания |
| Торвин выбирает средство, идёт и освобождает затвор | 15,67 | 7 956 / 429 | взятие до маршрута, затвор `clear` |

Это успешные карточки после исправления. Три предшествующих живых ответа были отклонены без изменения мира и не включены в таблицу как успехи.

Групповая заявка на объявленном затворе вернула одну проверку Торвина (`strength`, 13) и Миру как помощника. Локальный бонус составил `2 + 1 = 3`; тестовый бросок 2 выбрал уже готовую ветку неудачи без второго вызова. Оба героя одним исходом дошли до водозабора, затвор остался `jammed`. Карточка заняла 15,78 с; usage — 7 420 входных и 587 выходных токенов, из входа 2 816 отмечены CLI как cached. Два предыдущих ответа той же заявки помогли найти сравнение расширенной групповой проверки с авторским переходом; после исправления контрольный повтор прошёл.

Отдельная финальная заявка после локально подготовленного ремонта заняла 14,58 с (6 900 входных / 602 выходных токена). Luna вернула общий путь к Аде, передачу причины, `resolve_thread` и `finish_session(victory)`; после подтверждения нить разрешена, а сессия имеет состояние `finished`. Предыдущий ответ той же заявки предложил правильный финал, но пропустил служебную развязку нити. Нормализатор теперь добавляет её из явно предложенного финального итога и помечает карточку как `verdict`; повтор модели уже вернул полный набор самостоятельно.

Компактный JSON сцены на исходной площади занимает 5 964 символа вместо 8 845 у прежнего полного снимка. Однако маленькая живая выборка **не показывает пропорционального снижения входных токенов**: значительную часть занимают инструкция и строгая схема операций, а групповой/финальный контракт её расширил. Из схемы удалены декоративные `title` (примерно 19% её JSON), но экономию токенов нужно измерять на одинаковых повторных случаях и более крупном мире. Утверждать, что новая память уже радикально удешевила каждую карточку, нельзя.

Глобальный `codex` в PATH оказался версии 0.116.0 и был корректно отвергнут до вызова. Живые результаты получены проектной локальной CLI 0.154.0 — той, которую должен выбирать запуск с каталогом данных приложения.

## Последовательная проверка движка намерений — 2026-09-19

Временная игра, настоящий Codex CLI 0.154.0, Luna, без пользовательского сохранения. Проверялась одна причинная последовательность, а не независимые красивые ответы.

| Заявка | Секунды | Результат |
| --- | ---: | --- |
| Мира идёт через лес к водозабору и исследует затвор | 19,40 | Одна карточка: полный маршрут из трёх мест, `observe`, открытие причины с первого осмотра |
| Мира возвращается в мастерскую и сообщает Торвину причину | 15,59 | Одна карточка: обратный маршрут и постоянный `share_fact`; знание есть у обоих |
| Торвин выбирает средство, идёт к затвору и пытается освободить его | 21,59 | `transfer → move_path → set_state`; один заранее подготовленный бросок, затвор перешёл `jammed → clear` |

Первый прогон третьей заявки выявил общий пропуск рутинного шага: средство было указано в `using`, лежало рядом до выхода, но не было передано герою. Движок теперь детерминированно добавляет явный `transfer` такого свободно лежащего выбранного средства в обе ветки до маршрута. Полный повтор тех же трёх формулировок прошёл: успех даёт `transfer → move_path → set_state`, неудача сохранила бы `transfer → move_path`; состояние затвора меняется только при успехе.

Перед первой генерацией три обращения были отклонены Codex как неподдержанная строгая JSON Schema; мир не менялся. Адаптер теперь централизованно делает все свойства обязательными и удаляет неподдержанные `default`/`minItems`. После исправления и локального дополнения рутинного взятия предмета вся последовательность прошла от начала до подтверждённого изменения состояния.

Раздел ниже относится к прежнему контракту отдельных карточек и не является приёмкой текущего движка.

2026-09-16. Linux, Codex CLI 0.154.0, личный вход ChatGPT, **gpt-5.6-luna**, low reasoning. Отдельные временные игры. Платный API не использовался, пользовательская партия не участвовала.

## Что нашли и исправили

1. Первый отдельный вызов (13,29 с) вернул имя героя вместо ID NPC в `speaker`. Код отклонил ответ без изменения мира. Добавлены допустимые ID соседних NPC прямо в схему генерации и явное пояснение в инструкции. Это дополнительный вызов сверх девяти в таблице; всего за проверку выполнено десять запросов.
2. В четвёртом случае таблицы модель описала переход, но вернула лишь создание места. Код оставил героя на прежнем месте. Инструкция теперь явно различает create и move; весь список эффектов и рассчитанные место/HP/вещи вынесены на карточку. Целевой повтор вернул обе операции. Это не доказательство невозможности последующих смысловых ошибок.
3. Подсказки были длиннее необходимого. Ограничены длины полей, указано давать 1–2 коротких указания. Проверяющий и рассказчик не возвращены на обязательный путь.

[Сохранённые ответы и измерения](evals/gm-assistant-2026-09-16.json) содержат только вымышленный проверочный сценарий, без личного сохранения и авторизации.

## Автоматические и браузерные проверки

Раздел ниже фиксирует прежний срез из **156 тестов**; актуальная сумма находится в [сводке проверок](VERIFICATION.md). Ruff и проверка синтаксиса JavaScript были без ошибок. Заключительный браузерный прогон прошёл.

- Один запрос для новой карточки, обе ветки до кубика, отсутствие обращения после броска/при правке/при принятии.
- Советы не исполняют механику и не становятся фактами; выбрано правильное действующее лицо, в том числе второй герой.
- Отображаемый расчёт состояния строится по операциям, даже если текст ошибочно обещает перемещение.
- Запрет неизвестных предметов, повторного расхода, невалидного второго эффекта; отмена, повтор доставки, устаревший ответ, отказ/перезапуск провайдера.
- Свой лор и авторская тайна попадают в контекст; 40 локальных записей → экспорт/импорт → отмена → ранний факт остаётся доступным. Это детерминированная проверка памяти, не 40 живых LLM-ходов.
- Проверка неверных документов, версий, ссылок, повторных событий и невозможного журнала без изменения активной игры; контроль доступа ко всем маршрутам.
- Браузер: карточка, редактирование, перезагрузка, физический бросок, принятие, отмена, локальный переход, импорт мира с двумя героями, вопрос ведущего, выгрузка и загрузка журнала, узкое окно 390 px.
