# Codex: подключение текущего помощника

[← Путеводитель](README.md) · [Первый запуск и первая сцена](PLAYER_SETUP.md) · [Передача приложения ведущему](DISTRIBUTION.md)

Описание **реализованного адаптера репозитория** на 2026-09-22. Источник: [codex_provider.py](../dnd_helper/codex_provider.py). Проверенная среда — Linux, CLI 0.154.0 или новее, личный вход через ChatGPT; Windows и будущие версии требуют отдельной проверки.

## Вход ведущего

Codex устанавливается отдельно от приложения. Адаптер ищет его в `PATH`; для нестандартного расположения есть переменная `DND_CODEX_BINARY`. Через **«Настройки → Войти через ChatGPT»** запускается штатный `codex login`, а **«Проверить вход»** вызывает проверку версии и `login status`.

Приложение допускает CLI не ниже 0.154.0 и проверяет именно вход через ChatGPT. Оно не копирует токены в свою базу. При установке CLI через npm на Windows адаптер разрешает `.cmd`/`.ps1` в JS-точку входа, поэтому этой установке нужен Node.js. Установка самого веб-приложения и установка CLI — разные зависимости.

Модель выбирается в настройках, по умолчанию Luna. Выбор сохраняется в базе приложения и фиксируется на запрос; личные настройки Codex для разработки не изменяются. Во время незавершённого хода модель не переключается.

## Вызов и результат

- В прежнем `/world` каждая карточка запускает новый `codex exec --ephemeral`; `resume` и `--last` там не используются.
- Экспериментальный `/studio` лениво запускает постоянный `codex app-server --stdio` для строгой игровой беседы, создаёт или возобновляет тред по точному ID и передаёт ходы через `turn/start`. Досье передаётся при старте, а не повторяется каждый ход; схема результата применяется к каждому ответу. Полный контекст можно напомнить вручную.
- Независимый режиссёрский наблюдатель `/studio` использует второй лениво запущенный App Server и другой ID треда. Поэтому он может оценивать подтверждённую игру в фоне, пока инициатива у игроков, и не блокировать следующий игровой запрос. Игровой и режиссёрский контексты не продолжают тред друг друга.
- `/world` передаёт ограниченную папку одного хода. В неё не входят полный документ, весь журнал и старые модельные ответы.
- Игровой `/studio` при старте передаёт полное короткое досье, капсулу и принятый диалог. На продолжениях передаются новая реплика и накопившиеся решения ведущего. Наблюдатель при первом запуске также получает досье и подтверждённую историю, а затем текущую капсулу и только новые принятые события. Сохранённые самой CLI файлы тредов нужны для возобновления после перезапуска и остаются в локальном каталоге Codex, но не входят в Git или игровой экспорт.
- JSONL-протокол App Server идёт по stdin/stdout без shell. Рабочий каталог нейтральный; временный каталог существует только пока жив процесс и удаляется при остановке приложения.
- Инструменты, веб, плагины и делегирование выключаются настройками; схемы ограничивают ссылки текущими ID. Вывод повторно проверяется Pydantic и игровым кодом.
- Обнаруженное событие использования инструмента отклоняет ответ. Это дополнительная защита, а не гарантия полной изоляции CLI на любой машине.
- Тайм-аут адаптера — 120 секунд. Игровой ход можно прервать через `turn/interrupt`; при остановке приложения завершается вся группа процесса. Это предел ожидания, не ожидаемая скорость игры.
- Ошибки входа, лимита, формата и тайм-аута дают понятное сообщение. Сырые stderr и секреты не выдаются браузеру.

В `/world` карточка содержит смысловые эффекты, которые компилируются в точные операции. В `/studio` карточка предлагает только дельту капсулы; приложение локально вычисляет полное состояние, а оно не становится авторитетным до подтверждения ведущего. Оба режима готовят ветки кубика в одном ответе и не делают скрытого повторного запроса. [Описание IDE](GAME_STUDIO.md).

## Лимиты и учёт

Диагностика хранит число вызовов, время до первого события, время до первого фрагмента текста, полную длительность, модель и usage конкретного хода. Вызовы наблюдателя помечены как `director`, поэтому их дополнительную стоимость можно считать отдельно. App Server отдельно присылает накопительный usage треда; он сохраняется для диагностики, но не используется как usage хода. Подписочные токены не пересчитываются в доллары. Приложение не обещает известный остаток подписки или достаточность лимита на определённое число игр.

Прежняя накопительная реализация была удалена после пользовательского прогона: 19 вызовов израсходовали 1&nbsp;802&nbsp;540 входных токенов, а один вход достиг 291&nbsp;721. Она повторяла большие схемы и контекст и тащила за собой неудачные черновики. `/studio` возвращает накопительную беседу как новый ограниченный эксперимент: досье даётся один раз, схема технически применяется к каждому ответу, решения ведущего идут дельтами, а перезапуск остаётся ручным. Во втором живом прогоне 21 успешный ход использовал 389&nbsp;023 входных токена, из них 308&nbsp;736 кэшированных, и 19&nbsp;206 выходных; медиана ожидания составила 20,53 с.

При ошибке **нет автоматического перехода на API**. Для `/world` платный API-провайдер ещё не реализован; согласованный потолок $5 на сессию относится к будущему отдельному варианту. API-настройки подготовленного режима не включают API для нового помощника. Настройки расходов самого аккаунта Codex приложение не контролирует.

## Что проверено и что дальше

Подставные процессы проверяют эфемерный вызов `/world`, повторно используемый процесс App Server, продолжение треда, обязательную схему, потоковые метрики и сжатие. Локальные тесты `/studio` проверяют дельту, транзакцию принятия, локальный бросок, приватность Совета/Мета, осторожный запуск сжатия и изоляцию наблюдателя. Два прежних живых прогона лабораторного среза выполнены; второй прошёл без форматных повторов. Второй App Server и качество живых режиссёрских оценок ещё не проверялись на подписке. Обычный CI не обращается к личной подписке.

Финальная двухходовая живая проба Luna через App Server дала 9,73 с до полного первого ответа и 3,92 с до второго; первый текст появился через 3,32 и 2,13 с. Второй ход продолжил тот же процесс и тред, 9 984 из 10 885 входных токенов были кэшированы. Это smoke-тест, а не медиана партии.

`thread/compact/start` проверен отдельно. На короткой двухходовой истории он занял около 32 с, а следующий вход вырос с 11 917 до 12 533 токенов и потерял кэш. Поэтому сжатие включено только как редкое обслуживание длинного треда: после 16 ходов, при последнем входе от 40 000 токенов и на безопасной границе сцены. Его польза должна быть повторно измерена на длинной партии.

Для передачи нужны отдельная проверка Windows-установки/входа и живая законченная партия на 90–120 минут. Telegram и распознавание речи не подключены к этому адаптеру. [План поставки](DISTRIBUTION.md).
