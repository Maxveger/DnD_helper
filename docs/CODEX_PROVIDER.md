# Codex CLI для свободного мира

Решение пользователя от 2026-09-16. **Статус: требования к реализации; адаптер ещё не написан.** Дополняет [ТЗ свободного мира](FREE_WORLD_SPEC.md).

## Выбранная схема

Основной способ обращения к LLM — официальный Codex CLI на ноутбуке ведущего, с входом ведущего в собственный аккаунт ChatGPT. Это вариант для обычных игр, а не только для отладки. Приложение используется в личной некоммерческой игре; перепродажа доступа, передача аккаунта и обход ограничений не предусматриваются.

OpenAI Responses API остаётся отдельным сменным провайдером. Переключение выбирает ведущий. Ошибка Codex или исчерпание подписочного лимита **не включает платный API автоматически**. Для API сохраняется согласованный предел $5 на игровую сессию, включая распознавание речи. Текст через Codex не требует API-ключа.

Официальная документация описывает [неинтерактивный запуск, JSON Schema и сохранённую авторизацию](https://learn.chatgpt.com/docs/non-interactive-mode), а также [вход через ChatGPT и API](https://learn.chatgpt.com/docs/auth). Это техническая основа интеграции, не отдельное подтверждение OpenAI для нашего продукта. Пользователь выбрал эту схему после обсуждения неопределённости условий; такого подтверждения мы не получали.

## Граница между моделью и приложением

```text
Действие → контекст из SQLite → LLM-провайдер → предложение
         → проверки приложения → решение ведущего → запись в SQLite
```

- Одинаковые входы, схемы ответов и ошибки для Codex и API. Провайдер возвращает предложение; сам он не изменяет игру.
- Память, факты, знания NPC, кубики, очередь и подтверждения принадлежат приложению. Смена провайдера не требует новой игры и не переносит память между чатами.
- Каждый запрос получает заново собранный контекст конкретного этапа. Не используются текущий разговор разработки, `resume --last` и общий сеанс для секретного планировщика и публичного рассказчика.
- Планировщик, проверяющий и рассказчик вызываются только по правилам игрового шага. Сохраняется максимум пять генеративных вызовов на действие из основного ТЗ. Нет фонового опроса модели и бесконечного автоматического повторения ошибок.

## Требования к запуску CLI

1. Ведущий отдельно устанавливает официальный Codex и выполняет штатный вход через ChatGPT. Приложение проверяет доступность CLI и тип авторизации без чтения и копирования токенов. В подписочном режиме авторизация API-ключом должна давать понятное сообщение о несоответствии режима, а не платный вызов.
2. Адаптер запускает `codex exec` отдельным процессом, передаёт контекст через stdin и запрашивает ответ через `--output-schema`. Аргументы передаются массивом без shell; текст игрока не становится командой оболочки.
3. Новый временный рабочий каталог на запрос, эфемерный сеанс, запрет интерактивных запросов разрешений. JSON повторно проверяется локально; соответствие схеме не заменяет проверку смысла и механики.
4. Игровой модели не нужны файловые операции, команды, веб-поиск, MCP, плагины и делегирование. Их отключение и влияние пользовательских настроек проверяются на поддерживаемой версии CLI. Один лишь режим read-only не запрещает чтение файлов: доступ к проекту, базе и посторонним секретам нельзя считать закрытым только из-за временного каталога или инструкции в промпте. До живого прогона нужно проверить фактическую изоляцию.
5. Тайм-аут, отмена и завершение приложения останавливают дочерний процесс; запоздалый ответ отвергается по ID шага и версии мира. Сбой не расходует игровые предметы и не назначает персонажу поражение.
6. Сырые stderr, токены входа и личные настройки CLI не передаются в браузер, Telegram, экспорт или CI. Для ведущего — понятная причина и следующий шаг; для диагностики — безопасные коды ошибок.

## Лимиты и диагностика

Подписка ограничена; обещания «хватит на две игры в неделю» пока нет. Измеряем живую игру на 30–40 минут: число вызовов, доступные данные usage, задержки, ошибки и ручные вмешательства. [Лимиты Codex](https://learn.chatgpt.com/docs/pricing) зависят от плана и характера задач.

В интерфейсе различаются расход API в долларах и использование Codex по подписке. Не переводим подписочные токены в выдуманную долларовую стоимость и не показываем неизвестный остаток как полный лимит. Если CLI не сообщает остаток, показываем «остаток смотрите в Codex». Учёт вызовов и usage сохраняется независимо от отмены игрового действия; отсутствие usage отмечается явно.

При исчерпании лимита — сохранение текущего шага, ручное продолжение или повтор по выбору ведущего после восстановления доступа. Уже готовое предложение можно принять без нового запроса. Купленные кредиты и их расход могут определяться настройками аккаунта Codex: приложение не обещает контролировать его биллинг. Лимит $5 управляет только нашим API-адаптером.

## Установка, голос и проверка

- Готовый Windows-пакет приложения по-прежнему не требует Python. Режим Codex добавляет отдельную зависимость — установленный CLI и вход в аккаунт; это нужно отразить в мастере подключения и инструкции. Проверяем Linux и Windows отдельно.
- Telegram передаёт текст тому же обработчику. Пользователь согласовал распознавание голосовых отдельным сервисом: текущий речевой API требует ключа и учитывается в $5; подписочное распознавание через CLI не заявлено. Без него доступны текст и ручной ввод расшифровки.
- Первые тесты используют подставной процесс: JSON, отказ входа, лимит, тайм-аут, неверная схема, отмена, повтор и отсутствие скрытого перехода на API. Обычный CI не использует личный аккаунт и не вызывает модель.
- Затем выполняются ограниченный живой запрос и игровая сессия. Приёмка выбранного Codex-провайдера не требует API-ключа; готовность альтернативного API подтверждается отдельным прогоном.

## Следующий этап разработки

Контракты свободного действия и памяти → адаптер Codex → один полный ход в веб-интерфейсе → длинная игра и проверка устойчивости → Telegram/голос и Windows-поставка. Текущий закрытый классификатор старых приключений не считается реализацией свободного мира.
