# Текущий этап: свободный мир с LLM

Зафиксировано: 2026-09-15. Обновлено: 2026-09-16, по решению пользователя.

**Приоритет:** после исправления трёх замечаний к вариантам действий пользователь поручил перейти к свободному миру. Подготовлено [новое ТЗ](FREE_WORLD_SPEC.md), согласованы Codex CLI по подписке ведущего как основной провайдер, $5 на API-вызовы и принятие обычного исхода одним нажатием. [Требования к Codex](CODEX_PROVIDER.md). Следующий шаг — контракты памяти и общий обработчик свободного действия. Новая механика ещё не реализована; остальные проверки интерфейса ниже остаются задачами и не объявлены завершёнными.

## Откуда продолжаем

- Пользователь прошёл встроенное приключение после исправления зависшей очереди.
- Демо допускает полный финал, ограничений по времени или числу нажатий нет.
- В текущих исходниках быстрые кнопки учитывают героя, цель и правила. После доработки 2026-09-16 недоступные и выполненные одноразовые варианты скрываются, переходы с названием места находятся в том же списке. Можно заменить ошибочную заявку или явно отменить её вместе с очередью.
- Добавлены подсказки следующего шага. Исправлены назначение выбывшего героя первым в бою и положение группы после отступления.
- Последний выполненный прогон (2026-09-16): 114 тестов, включая 27 полных маршрутов; браузерная проверка доступных вариантов, переходов, восстановления очереди, боя и финала, а также импортированного приключения. Подробности — в [VERIFICATION.md](VERIFICATION.md).
- Опубликованный Windows `v0.1.0-rc.1` этих исправлений ещё не содержит. Локальные исходники и старый релиз нужно различать.
- Живые запросы GPT/Telegram и полноценная свободная игра пока не проверены. Для нового режима выбран Codex CLI; адаптер ещё не реализован. API остаётся альтернативой с лимитом $5 на сессию; конкретные модели ещё не выбраны.

## 1. Оставшиеся проверки интерфейса

Ниже — области проверки, а не список уже подтверждённых дефектов. Начать с замечаний пользователя и прохода по реальному интерфейсу. Для каждого найденного затруднения записывать: действие пользователя → что произошло → чего он ожидал.

- [ ] Главный экран: сразу видно, кто действует, что происходит и какого нажатия ждёт приложение.
- [ ] Выбор героя и цели: различимы автор и адресат действия; автоматическая смена хода не сбивает с толку.
- [x] Быстрые действия: недоступные и выполненные одноразовые варианты скрыты; список учитывает выбранного героя и цель. Проверено автоматически; дальнейшая оценка удобства — с пользователем.
- [x] Переходы: добавлены в общий список с названием локации; отдельная кнопка «Сменить локацию» убрана. Проверены также несколько выходов импортированного приключения.
- [ ] Бросок и исход: различимы предложение проверки, ожидание числа, результат и применение последствий. Понятно, когда нажать «Продолжить».
- [ ] Ошибочная заявка и очередь: видно, что будет заменено или отменено; повторные нажатия не выглядят как продвижение игры, если лишь добавляют заявки.
- [ ] Ручное решение и отмена: доступны в нужный момент, смысл и последствия кнопок понятны новичку.
- [ ] Тексты: подсказки ведущему, реплики для чтения игрокам и секреты различимы; нет лишнего технического текста в основном игровом потоке.
- [ ] Карточки и журнал: здоровье, предметы, открытия и последние последствия легко найти; обновления не сбрасывают работу с интерфейсом.
- [ ] Пауза, перезапуск и финал: понятны состояние игры и способ продолжения; нет необходимости начинать заново.
- [ ] Экран ноутбука и узкое окно: основные элементы доступны, нет горизонтального переполнения и неудобного постоянного прокручивания.

Для этих проверок используем текущие истории и механику. Ключи и платные вызовы для доводки интерфейса не требуются. По новому указанию пользователя незакрытый общий список проверки удобства не блокирует реализацию свободного мира.

### Когда этот этап завершён

- Пользователь проходит сцену и приключение без внешних объяснений о том, куда нажать дальше.
- Закрыты найденные препятствия и неоднозначные действия интерфейса.
- Подтверждены мирный путь, путь с провалом/боем и восстановление после ошибочного ввода; импортированные истории продолжают работать.
- Для изменённого поведения выполнены подходящие проверки. Пользовательское сохранение не используется для разрушительных тестов.
- В документации различаются проверенные исходники и готовая сборка. Новая поставка на Windows проверяется отдельно при её подготовке.

## 2. Следующая работа — прототип свободного мира

1. Реализовать контракты сущностей, фактов, знаний и событий и общие операции по новому ТЗ. Перед живым прогоном выбрать доступную модель Codex и проверить вход ведущего.
2. Реализовать общий контракт провайдеров и адаптер Codex CLI: штатный вход, изоляция, JSON Schema, тайм-аут, отмена и обработка лимитов. API остаётся отдельно выбираемой альтернативой ($5 на сессию); скрытого платного переключения нет. Для голоса согласовано отдельное распознавание через API в том же бюджете.
3. Сделать один свободный ход: предложение → проверка → бросок при необходимости → принятие ведущим → сохранение и выдача реплики.
4. Проверить неожиданные действия и длительную историю, измерить задержку, использование подписки и вмешательства ведущего. Живую проверку API и его расходов выполнить отдельно при подключении этого варианта.
5. По результатам закрепить новый документ автора и расширять мир, сохраняя старые приключения.

Объём реализации, контракты, лимиты и приёмка — в [FREE_WORLD_SPEC.md](FREE_WORLD_SPEC.md). Исходные принципы и защита от противоречий — в [HYBRID_WORLD.md](HYBRID_WORLD.md).

## Запуск для продолжения

Из корня репозитория на подготовленном Linux:

```bash
./start.sh --data-dir ./data
```

Открывать адрес, который сообщает приложение: порт может измениться. Для автоматических браузерных проверок использовать изолированный экземпляр; `scripts/browser_gameplay_check.py` и `scripts/browser_import_check.py` создают его по умолчанию.
