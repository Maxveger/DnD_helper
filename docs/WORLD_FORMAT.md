# Свой мир и переносимый журнал

[← Путеводитель](README.md) · [Первый запуск и первая сцена](PLAYER_SETUP.md) · [Устройство приложения](ARCHITECTURE.md)

Текущий помощник ведущего (`/world`) принимает **`dnd-world@1`** и **`dnd-world-log@1`**. Для подготовленного режима используется отдельный [формат `dnd-adventure@1`](ADVENTURE_FORMAT.md); документы не взаимозаменяемы.

## От обсуждения в GPT до игры

1. Откройте **«Настройки → Своя история и журнал → Комплект для GPT»**.
2. Передайте комплект в браузерный чат GPT. Он включает инструкции автора, схему из моделей приложения и полный пример.
3. Обсудите мир, тон, героев, тайну, NPC и правила. Попросите итоговый JSON для приложения. Для первого прогона достаточно 30–40 минут и 1–2 игроков.
4. Вставьте документ или загрузите файл. Нажмите **«Проверить документ»**: это локальная проверка, без обращения к модели и без изменения игры.
5. При ошибках верните готовый отчёт в тот же чат. При успехе явно начните игру с документом. Сохраните журнал прежней партии, если она нужна.

Полный пример текущего мира: [example-world.json](../dnd_helper/resources/example-world.json). Источник контракта и авторского промпта: [world_documents.py](../dnd_helper/world_documents.py). Отдельный [AUTHOR_KIT.md](AUTHOR_KIT.md) предназначен для прежних подготовленных приключений.

## Что содержит `dnd-world@1`

| Поле | Содержание |
| --- | --- |
| `format`, `id`, `version`, `title` | Тип документа, постоянный идентификатор, версия вида `1.1.0`, название |
| `lore` | Связное описание мира, атмосферы, быта и особенностей |
| `intro` | Готовое вступление, которое можно читать игрокам |
| `gm_notes` | Фабула, причины событий, мотивы и речь NPC, ориентиры для ведущего |
| `boundaries` | Границы импровизации: что нельзя менять или добавлять |
| `rules` | Исполнитель `hybrid-simple@1` и явно ручные `manual_rules` |
| `entities` | Герои, локации, NPC, предметы; ID, описание, положение/владелец |
| `facts` | Факты, утверждения, слухи и обещания; видимость и носители знания |
| `connections` | Пары связанных локаций для известных переходов |

Важную неизменную тайну следует выразить записью в `facts` с видимостью `gm`, а её сюжетное объяснение — в `gm_notes`. `known_by` задаёт, какие персонажи знают запись. Не помещайте тайну в публичное вступление или описание комнаты.

Поддержаны 1–4 героя; у каждого HP, максимум HP и характеристики `strength`, `agility`, `mind`. Это упрощённый исполнитель, не полная редакция D&D. Свободное описание новой системы правил не добавляет её автоматическое исполнение.

## Что проверяет приложение

JSON до 500 000 байт; до 60 сущностей, 200 фактов и 100 связей. ID имеют ограниченный формат. Отклоняются неизвестные поля/версии, повторяющиеся ID/имена сущностей, неправильные ссылки, места и владельцы, невозможные HP и неизвестные носители знания. Документ не исполняет код и не загружает ссылки.

Валидный документ может оставаться сюжетно слабым или противоречивым: проверка структуры не заменяет чтение ведущим. Список точных ограничений формируется в JSON Schema комплекта; при изменении кода используйте свежий комплект.

## Продолжение из `dnd-world-log@1`

Кнопка **«Скачать журнал»** сохраняет закреплённый стартовый `document` и принятые `events` (до 200). При загрузке программа повторно проверяет мир, броски и последовательность операций, затем восстанавливает состояние. Невозможный расход, дубликат события или ошибочная ссылка отклоняются с указанием места ошибки.

В файле нет ключей, авторизации, диагностики запросов или неподтверждённой карточки. **Тайны ведущего есть.** Для нескольких партий храните отдельные файлы журналов: в приложении одна активная игра этого режима. Обычный перезапуск из SQLite сохраняет больше служебного состояния, чем переносимый журнал.

Произвольный текстовый лог не является исполняемым журналом. Его можно обсудить в авторском чате и перенести согласованные события в стартовые факты и состояние по схеме, без выдумывания бросков.
